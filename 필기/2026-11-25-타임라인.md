[09:33] java 에서 inteface의 메서드를 오버라이딩 할 때 Inner Class 로 구현 하는 경우를 설명하세요.

[09:33] Iterable 의 default void forEach(Consumer<? super T> action)

[09:33] Consumer 를 inner class, 람다표현식, Method Reference 로 표현하는 단계별 설명이 필요함

[09:33] Java에서 인터페이스의 메서드를 구현할 때 이너 클래스(Inner Class, 내부 클래스)를 사용하는 이유는, 해당 구현체가 특정 클래스 내부에서만 쓰이거나 외부 클래스의 멤버(필드·메서드)에 자연스럽게 접근해야 할 때 불필요한 최상위(Top-level) 클래스를 늘리지 않고 코드를 응집도 있게 묶기 위해서입니다.

[09:33] 특히 Iterable.forEach(Consumer<? super T> action)처럼 함수형 인터페이스(추상 메서드가 하나인 인터페이스)를 인자로 받는 메서드에서는, 이너 클래스로 시작해 람다 표현식(Lambda Expression)과 메서드 참조(Method Reference)로 점진적으로 간결하게 줄여 나갈 수 있습니다.

[09:33] 전제: Iterable.forEach와 Consumer
[09:33] List<String> 같은 컬렉션은 Iterable<T>를 구현하고 있으며, 다음 default 메서드를 가집니다.

[09:33] Java
[09:33] default void forEach(Consumer<? super T> action)
[09:33] Consumer<T>는 T 타입의 인자를 하나 받고 반환값이 없는(void accept(T t)) 함수형 인터페이스입니다.

[09:34] - `Iterable`의 `default void forEach(Consumer<? super T> action)`
[09:34] - 컬렉션 요소를 하나씩 꺼내 `action.accept(요소)`를 부름
[09:34] - `Consumer<T>`: `void accept(T t)` 하나뿐인 함수형 인터페이스 (받기만 하고 반환 없음)
[09:34] - 이너 클래스를 쓰는 이유: 그 클래스 안에서만 쓰는 구현체라서 최상위 클래스를 따로 만들지 않으려고. 바깥 클래스의 필드·메서드에도 바로 접근 가능
