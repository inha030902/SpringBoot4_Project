## 파트1 (09:05~09:55)
### 질문: 인터페이스 메서드를 Inner Class로 구현하는 경우 / Consumer를 단계별로 줄이기

- `Iterable`의 `default void forEach(Consumer<? super T> action)`
  - 컬렉션 요소를 하나씩 꺼내 `action.accept(요소)`를 부름
- `Consumer<T>`: `void accept(T t)` 하나뿐인 함수형 인터페이스 (받기만 하고 반환 없음)
- 이너 클래스를 쓰는 이유: 그 클래스 안에서만 쓰는 구현체라서 최상위 클래스를 따로 만들지 않으려고. 바깥 클래스의 필드·메서드에도 바로 접근 가능

### 4단계로 줄이기 (예: `names.forEach(...)`로 이름 출력)

```java
// 1) 이름 있는 이너 클래스
private class PrintConsumer implements Consumer<String> {
    @Override
    public void accept(String name) { System.out.println(name); }
}
names.forEach(new PrintConsumer());

// 2) 익명 이너 클래스: 선언과 생성을 인자 자리에서 한 번에
names.forEach(new Consumer<String>() {
    @Override
    public void accept(String name) { System.out.println(name); }
});

// 3) 람다: 인터페이스 이름, 메서드 이름(accept), 반환 타입 생략
names.forEach(name -> System.out.println(name));

// 4) 메서드 레퍼런스: 받은 값을 그대로 넘기기만 할 때
names.forEach(System.out::println);
```

| 방식 | 언제 쓰나 |
| --- | --- |
| 이름 있는 이너 클래스 | 로직이 길거나, 필드(상태)를 갖거나, 여러 곳에서 재사용 |
| 익명 이너 클래스 | 추상 메서드가 여러 개라 람다를 못 쓸 때 |
| 람다 | 한 번 쓰는 콜백, 조건문 등 직접 로직이 있을 때 |
| 메서드 레퍼런스 | 기존 메서드 호출만 할 때 |

- 주의: 람다 안에서 쓰는 바깥 지역 변수는 사실상 final(effectively final)이어야 함
- 어제 MyRunner의 `optionNames.forEach(...)`가 3·4단계

### `<finalName>`: 빌드 결과물 이름 정하기

```xml
<build>
    <plugins>...</plugins>
    <finalName>myboot4</finalName>
</build>
```

- finalName 지정 후: `target/myboot4.jar`
- 실행: `java -jar target/myboot4.jar` (이름이 짧아 명령이 간단해짐)
- 이름만 바뀌고 jar 안의 내용은 같음

### HibernateProperties: `spring.jpa.hibernate.*` 설정을 담는 클래스

- `@ConfigurationProperties("spring.jpa.hibernate")`가 붙은 클래스
  - properties 파일에서 `spring.jpa.hibernate.`로 시작하는 값을 필드에 자동으로 넣어 줌 (앞에서 배운 `@Value`를 묶음으로 처리하는 방식)
- 위치는 버전에 따라 다름
  - Boot 3.5: `org.springframework.boot.autoconfigure.orm.jpa.HibernateProperties`
  - Boot 4.0(우리 프로젝트): `org.springframework.boot.hibernate.autoconfigure.HibernateProperties` (`spring-boot-hibernate` 모듈로 분리됨)

| 필드 | properties 키 | 뜻 |
| --- | --- | --- |
| `ddlAuto` | `spring.jpa.hibernate.ddl-auto` | 앱 시작 시 테이블 처리 방법 (`none`, `validate`, `update`, `create`, `create-drop`) |
| `naming.physicalStrategy` | `spring.jpa.hibernate.naming.physical-strategy` | 엔티티 이름 → DB 테이블·컬럼 이름 변환 규칙 |
| `naming.implicitStrategy` | `spring.jpa.hibernate.naming.implicit-strategy` | 이름을 직접 지정하지 않았을 때 정하는 규칙 |

```properties
spring.jpa.hibernate.ddl-auto=create
```

- `determineHibernateProperties(...)`: 표준 JPA 설정(`spring.jpa.properties.*`)과 위 값을 합쳐 Hibernate `EntityManagerFactory`를 만들 때 쓸 최종 설정 Map을 만듦
- 짝꿍 클래스 `JpaProperties`(`spring.jpa.*`): `show-sql`, `database-platform`, `open-in-view`, `properties` 등 JPA 공통 설정
- ddl-auto를 안 적으면: H2 같은 내장 DB는 `create-drop`, 그 밖의 DB는 `none`
- 참고: [HibernateProperties API (3.5)](https://docs.spring.io/spring-boot/3.5/api/java/org/springframework/boot/autoconfigure/orm/jpa/HibernateProperties.html)
