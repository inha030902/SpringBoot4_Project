## 파트1 (09:05~09:55)
java 에서 inteface의 메서드를 오버라이딩 할 때 Inner Class 로 구현 하는 경우를 설명하세요.

Iterable 의 default void forEach(Consumer<? super T> action)

Consumer 를 inner class, 람다표현식, Method Reference 로 표현하는 단계별 설명이 필요함

Java에서 인터페이스의 메서드를 구현할 때 이너 클래스(Inner Class, 내부 클래스)를 사용하는 이유는, 해당 구현체가 특정 클래스 내부에서만 쓰이거나 외부 클래스의 멤버(필드·메서드)에 자연스럽게 접근해야 할 때 불필요한 최상위(Top-level) 클래스를 늘리지 않고 코드를 응집도 있게 묶기 위해서입니다.

특히 Iterable.forEach(Consumer<? super T> action)처럼 함수형 인터페이스(추상 메서드가 하나인 인터페이스)를 인자로 받는 메서드에서는, 이너 클래스로 시작해 람다 표현식(Lambda Expression)과 메서드 참조(Method Reference)로 점진적으로 간결하게 줄여 나갈 수 있습니다.

전제: Iterable.forEach와 Consumer
List<String> 같은 컬렉션은 Iterable<T>를 구현하고 있으며, 다음 default 메서드를 가집니다.

Java
default void forEach(Consumer<? super T> action)
Consumer<T>는 T 타입의 인자를 하나 받고 반환값이 없는(void accept(T t)) 함수형 인터페이스입니다.

forEach는 컬렉션의 각 요소를 꺼내 action.accept(element)를 호출합니다.

단계별 구현 과정
리스트의 각 요소를 출력하는 예제를 기준으로 4단계로 변환해 보겠습니다.

Java
List<String> names = List.of("Kim", "Lee", "Park");
1단계: 이름이 있는 이너 클래스 (Named Inner Class)
외부 클래스 안에 private 또는 패키지 전용 이너 클래스를 정의하고 Consumer<String>을 구현합니다.

장점: 이름이 있어 가독성이 좋고, 여러 곳에서 재사용하거나 상태를 필드로 가질 수 있습니다.

단점: 한 번만 쓸 콜백이라면 보일러플레이트(반복 작성 코드)가 길어집니다.

Java
public class Example {

    // 이너 클래스로 Consumer 구현
    private class PrintConsumer implements Consumer<String> {
        @Override
        public void accept(String name) {
            System.out.println(name);
        }
    }

    public void run() {
        List<String> names = List.of("Kim", "Lee", "Park");
        names.forEach(new PrintConsumer());
    }
}
2단계: 익명 이너 클래스 (Anonymous Inner Class)
클래스 선언과 인스턴스 생성을 forEach(...) 인자 위치에서 한 번에 처리합니다.

장점: 별도의 클래스 이름을 짓지 않고 호출부 근처에 로직을 바로 둘 수 있습니다.

단점: public void accept(String name) 같은 선언부 형식이 여전히 장황합니다.

Java
public class Example {
public void run() {
List<String> names = List.of("Kim", "Lee", "Park");

        names.forEach(new Consumer<String>() {
            @Override
            public void accept(String name) {
                System.out.println(name);
            }
        });
    }
}
3단계: 람다 표현식 (Lambda Expression)
Consumer가 추상 메서드를 하나만 가진 함수형 인터페이스이므로, 인터페이스명과 메서드명(accept), 반환 타입을 생략하고 (파라미터) -> { 실행문 } 형태로 줄입니다.

장점: 핵심 동작(System.out.println(name))이 한눈에 들어오며 코드가 크게 줄어듭니다.

주의: 람다 내부에서 참조하는 외부 지역 변수는 사실상 final(effectively final)이어야 합니다.

Java
public class Example {
public void run() {
List<String> names = List.of("Kim", "Lee", "Park");

        names.forEach(name -> System.out.println(name));
    }
}
4단계: 메서드 참조 (Method Reference)
람다 본문이 이미 존재하는 메서드 하나를 단순히 호출하기만 할 때, 인자 전달조차 생략하고 대상::메서드명으로 표현합니다.

System.out 객체의 println 인스턴스 메서드를 참조하므로 System.out::println이 됩니다.

컴파일러가 Consumer<String>의 accept(String) 시그니처에 맞춰 println(String) 호출로 연결합니다.

Java
public class Example {
public void run() {
List<String> names = List.of("Kim", "Lee", "Park");

        names.forEach(System.out::println);
    }
}
한눈에 보는 비교
표현 방식	코드 형태	적합한 상황
이름 있는 이너 클래스	new PrintConsumer()	로직이 길거나, 상태(필드)를 유지하거나, 여러 곳에서 재사용할 때
익명 이너 클래스	new Consumer<String>() { ... }	추상 메서드가 여러 개인 인터페이스 구현이 필요하거나, 람다로 표현하기 어려운 구조일 때
람다 표현식	name -> System.out.println(name)	1회성 콜백이고, 조건문·복합 연산·외부 변수 조합 등 커스텀 로직이 있을 때
메서드 참조	System.out::println	기존 메서드 호출만 단순 위임해 가독성을 극대화할 때
